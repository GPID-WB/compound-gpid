## Findings And Dispositions

### P0.1 - Live closing-PR scan used unsupported pagination

External severity: critical. The implementation now makes one documented
`gh pr list --state open --json ... --limit 1000` request, rejects the obsolete
`--page` flag in the exact-argv regression test, and raises `ApiError` when the
configured limit is reached so a truncated result cannot produce READY.

### P1.1 - Typed GitHub payloads could escape the exit-code contract

External severity: major. GraphQL, repository, issue, and pull-request payload
shapes are validated before field access. Deliberate `null` issue/project values
remain absence; present malformed values raise `ApiError`, including a
non-string `nameWithOwner`.

### P1.2 - Fixture assignees and labels drifted from the gh wire format

External severity: major. The fixture uses `{ "login": ... }` and
`{ "name": ... }` objects. `FixtureClient` normalizes those objects and raises
`ConfigError` for malformed shapes, including a stale `headRef` key.

### P1.3 - Readiness implementation exceeded the 300-line rule

External severity: major. Contract parsing/rules, client implementations,
orchestration, rendering, and CLI responsibilities now live in separately
named modules. Every `scripts/issues/*.py` implementation module is below 300
lines. `readiness.py` remains the compatibility re-export facade.

### P1.4 - Phase 5 merge gate was not blocking

External severity: major. Decision D6 is now `blocking: true`; the active state
still records completed phases `[1, 2, 3, 4]` and current phase `5`.

### P1.5 - Archived v1 plan retained an active status

External severity: major. The explicitly archived and superseded v1 plan now has
canonical frontmatter `status: superseded`. Brain artifacts were regenerated by
`cg-index --brain`, not edited manually.

### P1.6 - Plan handoff still described the obsolete PR #128 gate

External severity: major. The plan now says: review and merge PR #135, then run
`/cg-work phase5`; Phase 5 must not run before this PR is merged.

### P1.7 - Python test-location guidance conflicted with native CI

External severity: minor. Repository evidence shows script-level pytest tests
are established under `scripts/tests/` and are explicitly registered in the
native-target job. The canonical Python instruction was corrected and all four
managed target copies were regenerated through `cg_generate_targets.py --all`.

### P1.8 - Execution report contradicted V9 and stale test counts

External severity: major. The report now keeps V8 pending, records V9 as
superseded, and records the final focused and native test results without the
obsolete 103-test claim.

### P2.1 - Readiness page was reported as orphaned

External severity: major. `docs/navigation.json` already contained the unique
`copilot-readiness` entry at the reviewed HEAD; no duplicate navigation edit was
made. `node scripts/check-docs-site.js` verifies complete navigation coverage.

### P2.2 - Markdown examples failed MD038/MD040

External severity: minor. The readiness page no longer has spaces immediately
inside inline code spans or an unlabeled fence. The documentation-site check
passes; the local markdownlint binary was unavailable in this offline
environment.

### P2.3 - Public readiness functions lacked complete docstrings

External severity: trivial. The requested public functions now document
parameters, returns, applicable exceptions, and accurate usage examples without
changing behavior.
