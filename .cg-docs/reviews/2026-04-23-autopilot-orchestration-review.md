### P0 — BLOCKING (immediate remediation required)

- **[P0.1]** [cg-adversarial + cg-version-control] `.github/hooks/hello-hook-guard.ps1`:41 — Hook log files written to tracked `.cg-docs/` will commit VS Code session data to git.
  **Why**: Line 41 writes the raw Stop hook stdin payload to `.cg-docs/autopilot-runs/poc-hook-input.json`. VS Code's hook payload may include conversation history, agent state, file path context, or session tokens. The project's `.gitignore` policy explicitly states `.cg-docs/ must be version-controlled`. One `git add .` after running `@cg-hello-hook` permanently exposes that payload in repo history. Once pushed, it cannot be removed without a destructive force-push across all clones.
  **Fix**: Add a scoped exception to `.gitignore` that preserves the "knowledge artifacts stay in git" policy for brainstorms/solutions while excluding PoC runtime logs:
  ```
  # PoC runtime artifacts — generated by hook scripts, not institutional knowledge
  .cg-docs/autopilot-runs/*.json
  ```
  Alternatively, write PoC logs to `$env:TEMP\cg-hooks\` (outside the repo entirely).

### P1 — CRITICAL (must fix before merge)

- **[P1.1]** [cg-data-quality] `.github/hooks/hello-hook-guard.ps1`:59 — `[bool]` cast silently mishandles string `"false"` and string `"0"`, breaking the anti-recursion guard.
  **Why**: `[bool]"false"` → `$true` in PowerShell. If the VS Code hook API ever sends `stop_hook_active` as the JSON string `"false"` (valid JSON, loosely typed), the script sets `$stopHookActive = $true` and **allows the stop when it should block**. This defeats the entire A4 validation criterion.
  **Fix**: `$stopHookActive = $hookData.stop_hook_active -eq $true` — equality comparison handles strings, null, and non-boolean values correctly.

- **[P1.2]** [cg-adversarial] `.github/hooks/hello-hook-guard.ps1`:41,64,79 — Unguarded `Set-Content` calls silently kill hook output on IO failure.
  **Why**: `Set-Content` throws a terminating exception on file lock (OneDrive sync, AV scan hold) or race. There is no `try/catch` around any of the three log writes. When an exception is thrown, the script exits without writing anything to stdout. VS Code receives no hook output — behavior is undefined (may silently allow stop).
  **Fix**: Wrap each `Set-Content` in `try/catch { <# logging failure — do not block hook output #> }`. Decouple logging from the hook's control flow.

- **[P1.3]** [cg-adversarial] `.github/hooks/hello-hook-guard.ps1`:41 — Race condition: concurrent invocations throw on shared log filename.
  **Why**: `Set-Content` on Windows opens files with exclusive write access. If VS Code fires two Stop events in rapid succession, the second invocation throws `IOException: file is being used by another process` — uncaught, script exits with no stdout.
  **Fix**: Use per-invocation timestamped filenames: `poc-hook-input-$(Get-Date -Format 'yyyyMMdd-HHmmss-fff').json`. Eliminates both the race condition and the log-overwrite issue (P3.8).

- **[P1.4]** [cg-learnings-researcher] `.github/hooks/hello-hook-guard.ps1`:32 — `[Console]::In.ReadToEnd()` blocked by PowerShell Constrained Language Mode (CLM) on enterprise WBG machines.
  **Why**: Past solution documents CLM enforcement on WBG machines blocking .NET method invocations. Hook would silently fail to read stdin — `$rawInput` stays `''`, A2 validation criterion unvalidatable.
  **Fix**: Replace with CLM-safe `$input` automatic variable:
  ```powershell
  $rawInput = ($input -join "`n")
  ```

- **[P1.5]** [cg-architecture] `scripts/link.ps1` — `$ManagedDirs` omits `"hooks"`, so the real hook scripts will never be junctioned into user projects.
  **Why**: `$ManagedDirs = @("prompts", "skills", "agents", "instructions")` does not include `hooks`. Once Phase 1 writes `autopilot-guard.ps1` and `autopilot-precompact.ps1`, they will work inside the compound-gpid repo but be absent from every linked user project. Agent Stop hook frontmatter references a non-existent path.
  **Fix**: Add `"hooks"` to `$ManagedDirs` before Phase 1 begins. Pre-Phase 1 gate item, not a PoC blocker.

### P2 — IMPORTANT (should fix)

- **[P2.1]** [cg-adversarial] `.github/hooks/hello-hook-guard.ps1`:27 — `Test-Path` doesn't check container type — crashes if path exists as a file.
  **Why**: If `.cg-docs\autopilot-runs` is accidentally a regular file, `Test-Path` returns `$true`, `New-Item` is skipped, and `Set-Content` on a child path throws uncaught. Script exits with no output.
  **Fix**: `if (-not (Test-Path $logDir -PathType Container)) { New-Item -ItemType Directory -Path $logDir -Force | Out-Null }`

- **[P2.2]** [cg-adversarial + cg-reproducibility] `.github/hooks/hello-hook-guard.ps1`:22 — `$PSScriptRoot` empty when script invoked via `-Command` rather than `-File`.
  **Why**: If VS Code invokes hook via `-Command "& '...'"`, `$PSScriptRoot` is empty. `Split-Path "" -Parent` returns `""`. `$logDir` becomes a relative path from CWD — logs land in unpredictable location with no error.
  **Fix**: `if (-not $PSScriptRoot) { Write-Error "Must be invoked with -File"; exit 1 }`.

- **[P2.3]** [cg-architecture] `.github/hooks/hello-hook-guard.ps1`:22 — `$PSScriptRoot` resolves to junction **target** (the install dir), not the user project workspace.
  **Why**: In linked user projects, `$PSScriptRoot` resolves to the physical compound-gpid clone path. Logs accumulate in the install dir, not the user's `.cg-docs/`. The real implementation must derive workspace root from the hook payload or `$PWD`. For Phase 0 PoC running inside compound-gpid repo itself, this is not a blocker — but A2 validation should check whether VS Code's stdin includes a workspace path field.

- **[P2.4]** [cg-version-control + cg-architecture] `.github/agents/cg-hello-hook.agent.md`:6 — `user-invocable: true` on a temporary PoC agent pollutes the agent picker.
  **Why**: Agent appears in VS Code's picker for all compound-gpid workspace users. "TEMPORARY" in description only visible post-selection.
  **Fix**: Set `user-invocable: false`.

- **[P2.5]** [cg-version-control] No formal cleanup tracking for PoC artifacts.
  **Why**: "Delete after Phase 0 validation" in comments is invisible once session context is lost.
  **Fix**: Add cleanup checklist to the plan file:
  ```

  - [ ] Delete .github/agents/cg-hello-hook.agent.md
  - [ ] Revert tests/model-assignments.Tests.ps1 sentinel 14 → 13

  ```

- **[P2.6]** [cg-data-quality] `.github/hooks/hello-hook-guard.ps1`:47-49 — malformed-JSON catch overwrites raw input log, destroying diagnostic data.
  **Why**: Catch block writes `{error: ..., raw: ...}` back to `$inputLog`, overwriting raw bytes. Re-encoding may escape/truncate special characters. A2 validation can no longer distinguish "hook fired with bad payload" from "hook never fired."
  **Fix**: Write error to separate file: `poc-hook-input-error.json`. Keep `poc-hook-input.json` as the unmodified raw log.

- **[P2.7]** [cg-learnings-researcher] `.github/hooks/hello-hook-guard.ps1` — PS5.1 encoding trap: non-ASCII characters in future edits could silently corrupt the AST.
  **Why**: Past solutions document that PS5.1 with non-BOM UTF-8 files silently misparsing non-ASCII characters. This is the first `.ps1` in `.github/hooks/`.
  **Fix**: Either add UTF-8 BOM, or enforce strict ASCII-only in comments — no curly quotes, em-dashes, etc.
