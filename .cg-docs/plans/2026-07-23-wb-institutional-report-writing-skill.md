# Plan: World Bank Institutional Report-Writing Skill

## Objective

Create `cg-skill-wb-report-writing`, a progressive-disclosure skill for drafting,
expanding, revising, summarizing, adapting across document types, reviewing, and producing eight
types of World Bank institutional documents. The skill must preserve source
integrity, visibly distinguish verification needs from final prose, and never
invent numeric facts or institutional positions.

## Context

The Skills Enhancement roadmap milestone already contains feature
`world-bank-institutional-report-writing-skill`. The approved brainstorm chose a
single thin `SKILL.md` router with per-document-type references. This Deep parent
plan owns shared contracts and final integration. Eight Standard child plans own
the document types independently so a missing source pack blocks only that child,
not other ready types.

`.github/skills/` is the canonical source. `.claude/`, `.agents/`, and
`.opencode/` are generated by `scripts/cg_generate_targets.py` and must not be
hand-edited. Use the `skill-creator` workflow to draft and evaluate the skill,
but place canonical repository assets under
`.github/skills/cg-skill-wb-report-writing/`.

Relevant prior lessons:

- Keep `SKILL.md` as a thin routing table and move depth into references.
- Add behavioral Pester tests for prose contracts, not existence checks alone.
- Resolve links relative to nested reference files; links from
  `.github/skills/<skill>/references/` need `../../../../` to reach repo root.
- Use fixed source-pack and evaluation-result paths plus an executed validator;
  `/cg-work` must not infer approval or completion from generic artifact names.

### Evidence Artifact Schemas

Each source pack is JSON at
`.github/skills/cg-skill-wb-report-writing/references/source-packs/<slug>.json`:

```json
{
  "schema_version": 1,
  "document_type": "<slug>",
  "status": "approved",
  "approved_by": "<non-empty reviewer identity>",
  "approved_on": "YYYY-MM-DD",
  "terminology_status": "approved|not-required",
  "terminology_sources": ["<stable URL or repo-relative path>"],
  "exemplars": [
    {
      "title": "<non-empty title>",
      "source": "<stable URL or repo-relative path>",
      "retrieved_on": "YYYY-MM-DD",
      "relevant_sections": ["<non-empty section>"],
      "authority_rationale": "<non-empty rationale>"
    }
  ]
}
```

`--require-approved` passes only when the file exists; `schema_version` is `1`;
`document_type` matches the requested slug; `status` is `approved`; reviewer
and ISO dates are valid; `terminology_status` is an allowed value; approved
terminology has at least one source; and `exemplars` contains exactly 2 or 3
records with every shown field non-empty and every source a URL or existing
repo-relative path.

Each result record is JSON at
`.github/skills/cg-skill-wb-report-writing/evals/results/<slug>.json`:

```json
{
  "schema_version": 1,
  "document_type": "<slug>",
  "status": "accepted",
  "eval_definition": ".github/skills/cg-skill-wb-report-writing/evals/types/<slug>.json",
  "benchmark": "<existing repo-relative benchmark.json path>",
  "grading": "<existing repo-relative grading artifact path>",
  "feedback": "<existing repo-relative feedback.json path>",
  "assertions": {"total": 1, "passed": 1, "failed": 0},
  "guardrails": {
    "numeric_fidelity": true,
    "citation_integrity": true,
    "institutional_position": true,
    "data_status_propagation": true,
    "country_sensitivity": true,
    "type_specific_checks": true
  },
  "human_accepted": true,
  "human_reviewer": "<non-empty reviewer identity>",
  "human_reviewed_on": "YYYY-MM-DD"
}
```

`--require-eval-pass` passes only when the file and every referenced artifact
exist; schema/type/status match; assertion `total` is positive, `passed` equals
`total`, and `failed` is zero; every guardrail is `true`; and human acceptance,
reviewer, and ISO date are present. `--require-child-plans-complete` passes only
when all eight registered child files exist, point back to this parent, and have
`status: completed` plus `completed-date` in frontmatter.

## Testing Strategy

Use three complementary layers:

1. **Structural and behavioral Pester tests**: Assert frontmatter, thin routing,
   expected references, source-pack blocking, marker grammar, all four safety
   guardrails, basic Quarto scope, and documentation registration. Add one
   dedicated assertion for each behavioral branch rather than relying on broad
   phrase-presence alternations.
2. **Child-plan skill evaluations**: Each child runs realistic with-skill/no-skill pairs for
   ordinary drafting and deliberate violations. Programmatically grade exact
   numeric preservation, forbidden invention, required markers, source status,
   section structure, and generated citations. Use human review for tone,
   readability, audience calibration, and exemplar fidelity.
3. **Deterministic evidence validation**: Validate fixed source-pack and result
  paths plus child-plan completion through `validate_wb_writing_skill.py`.
4. **Repository integration tests**: Generate platform trees, run targeted
   Python target/parity tests, and finish with the canonical unfiltered Pester
   runner. Pester commands must follow `cg-skill-pester-safety`; any run involving
   `prompt-tools.Tests.ps1` uses an execution subagent and `Run-Tests.ps1`.

No document-type phase is complete from file inspection alone. Its approved
source pack, behavioral checks, and adversarial evaluation evidence are required.

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Generic prose fails to distinguish eight document types | High | Gate every type on approved exemplars, encode audience/structure/anti-patterns separately, and run per-type fidelity reviews. |
| Fluent output invents figures, citations, dates, or institutional positions | Critical | Put source integrity before drafting, require placeholders/flags, and use adversarial assertions that fail on any unsupported specificity. |
| Marker syntax leaks author notes or hides verification needs | High | Use visible brackets for verification and HTML comments only for author notes; test rendering/source behavior in Markdown and basic Quarto. |
| Source packs are incomplete or inaccessible | High | Block only the affected type with an explicit missing-input list; do not publish provisional fidelity claims. |
| Style guidance becomes copied or stale | Medium | Distill rules in original language, cite authority/version, record retrieval dates, and review against current approved guidance. |
| Skill context becomes too large | Medium | Capture before/after context audits, keep `SKILL.md` thin, route to one type plus task-specific shared references, and test selective loading instructions. |
| Subjective evaluations produce false confidence | High | Combine objective guardrail/structure assertions with paired baselines and explicit user qualitative acceptance. |
| Generated platform trees drift from `.github/` | Medium | Generate with the canonical script and run target/drift tests; never hand-edit generated copies. |
| Sensitive country language becomes outdated | High | Require current user-supplied approved terminology/disclaimers and prompt rather than guessing. |

## Out of Scope

- Automated PIP, API, database, or web retrieval of statistics
- Full Quarto code-chunk execution or data binding
- Word, LaTeX, PDF, or institutional template typesetting
- Publication clearance, legal review, or management approval workflows
- Multi-author editing and collaboration
- Languages other than English
- Claiming document-type fidelity without its approved source pack
- Reproducing substantial exemplar wording or copyrighted publication text

### Boundaries

- Allowed: parent and eight child plans; canonical skill files; eight per-type

### Iteration Policy

1. Complete parent Phase 1 before starting any child plan.
2. Run any child plan whose source pack is approved, in any order; a blocked
  child records missing inputs and does not block another child.
3. Each child runs focused behavioral/adversarial checks and records accepted
  human feedback at its fixed result path; static inspection is insufficient.
4. Resume parent Phase 2 only after the validator confirms all eight child plans
  and result records are complete.
5. Under `deviation-policy: ask`, pause before changing marker syntax, source
  authority, child coverage, evidence paths, generated-target ownership, or
  evaluation/audit thresholds.

### Blocked-Stop Conditions

- Parent core contracts, baseline audit, or validator tests fail.
- The selected child plan lacks 2-3 approved exemplars or necessary terminology;
  only that child halts.
- A guardrail evaluation produces an invented figure, unmarked unsupported
  claim/citation, or invented institutional position.
- A fixed source/result record cannot be produced or validated.
- The final context audit reports a deterministic regression without an approved
  exception.
- Safe Pester execution or required target-drift tests cannot run or fail after local recovery.
- User review rejects document-type fidelity and no approved revision direction
  is available.
- Completing the work would require full Quarto data binding, external data
  retrieval, or another protected/out-of-scope capability.
