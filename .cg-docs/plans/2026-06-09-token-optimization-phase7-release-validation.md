### 1. Create the end-to-end validation checklist

- **Requirements**: R1, R2, R3, R10

  - Create or update a focused release artifact under `.cg-docs/cost/`, such as `.cg-docs/cost/token-optimization-release-checklist.md`

- **Details**:
  - Add a release-candidate validation checklist with static checks, Codex-side checks, and manual VS Code/Copilot checks.
  - Cover these runtime surfaces explicitly:
    - `/cg-plan`: emits the model-context note; respects branch offer behavior; creates a plan under `.cg-docs/plans/`; uses staged context loading; does not infer the hidden Auto-selected model.
    - `/cg-work`: loads the active plan; respects phase gates; preserves Pester safety instructions; performs mechanical self-review; defaults to review recommendation only.
    - `/cg-work review:auto`: resolves review mode through `.github/shared/review-routing.contract.md` and dispatches only the route-appropriate agent set.
    - `/cg-work review:manual`: dispatches no review agents and emits a structured `/cg-review <mode>` recommendation.
    - `/cg-work review:none`: dispatches no review agents and suppresses review handoff verbosity.
    - `/cg-review light`: resolves to the two-agent route.
    - `/cg-review data-risk`: resolves to the standard eight agents with mandatory data-quality, reproducibility, and testing emphasis.
    - `/cg-review full`: resolves to all ten agents, including `@cg-learnings-researcher` and `@cg-adversarial`.
    - `/cg-compound`: captures a solution, rebuilds Knowledge Brain when available, and only enriches context/wiki through its documented maintenance workflow.
    - `/cg-resume`: loads summary context and pending work without carrying unrelated roadmap or Brain records into the summary.
    - Knowledge Brain selective retrieval: reads `.cg-docs/BRAIN.md`, matches topic(s), opens only relevant `BRAIN-NN.md` section(s), and does not read `.cg-docs/brain-index.json` wholesale.
    - Model-picker behavior: ordinary model-picker prompts omit `model:`; Auto is described without naming the hidden underlying model; premium model use remains user-initiated or explicitly justified.
  - Mark each checklist item as one of:
    - `Static`: verified by file inspection, audit output, or tests.
    - `Codex`: verified by Python tests or audit command in this environment.
    - `VS Code/Copilot`: runtime behavior validated by the external harness.
- **Test Scenarios**:
  - Happy path: maintainer can follow the checklist from audit through VS Code runtime validation.
  - Edge case: Codex cannot run PowerShell/Pester; checklist keeps the VS Code/PowerShell gate explicit.
  - Error path: a failed guardrail, missing model-picker note, or broad context-loading regression is classified as blocker or follow-up with rationale.
- **Tests**:
  - Markdown review plus audit/test commands in Step 3.
- **Acceptance criteria**:
  - The checklist covers every runtime surface listed in R2.
  - Runtime-only checks are clearly assigned to GitHub Copilot / VS Code.
  - No new workflow behavior is introduced.

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Documentation changes accidentally imply new runtime behavior | Scope creep or prompt contract drift | Keep changes descriptive; do not edit prompts unless validation finds a blocker. |
| Static audit passes but VS Code/Copilot runtime behavior regresses | False release confidence | Keep manual runtime validation as an explicit release gate. |
| Audit warnings are ignored because failures are zero | Remaining broad-load risks may drift | Classify every warning as intentional, documentation-only, follow-up, or blocker. |
| `.cg-docs/inbox/` ideas are accidentally promoted to roadmap | Unapproved roadmap expansion | Mention inbox only as a holding area; do not process or link its ideas. |
| Pester cannot run in Codex | Incomplete validation evidence | Document Codex limitation and require VS Code/PowerShell safe runner before release. |
| `/cg-compound` captures lessons before validation is complete | Knowledge base records unverified behavior | Run compounding after checklist and available tests are complete; mark external validation status accurately. |
