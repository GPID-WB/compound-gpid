## Version, Source, Metadata And Baseline Contract (Blocked Draft)

The following freezes the intended interfaces for review; it is **not** approval to implement phase 2, and the baseline and gateway are unresolved.

- GPID four-part numeric tag: exact ASCII `vX.Y.Z.B`, regex `^v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$`, entire tag at most 255 ASCII bytes; each component at most 9007199254740991 (safe JSON/JavaScript integer). Empty, whitespace, Unicode digits, signs, leading zeroes, suffixes, oversized numeric fields and overlong tags fail. Generic controller versions retain strict SemVer; historical four-part tags retain exact bytes and their separate reader lane. No SemVer/PEP 440 projection or special build-metadata encoding is permitted.
- GPID request/persisted identity: explicit `kind: gpid-four-part` in GPID-only schema extension; `version` is the unchanged unprefixed four-part string, `tag` unchanged prefixed tag, with exact bytes in proposal/request/journal/manifest/payload/Release/attestation. Three-part official tags remain `kind: semver` with the present generic contract. A GPID four-part tag is always classified prerelease, even when a historical GitHub Release has `prerelease:false`; never silently rewrite a historical Release. A historic four-part adoption needs its exact audited legacy identity and separate stable projection only where explicitly reviewed. The `kind` addition is a future schema decision that needs review before coding.
- Order and collisions: numeric core orders across lanes; for identical core, four-part builds order by numeric B, before SemVer prereleases and the official stable. For example `v1.2.0.9019 < v1.2.0.9020 < v1.2.0`. Stable selection uses only real three-part adopted stable entries plus verified stable docs baseline, never a four-part tag merely marked non-prerelease by GitHub. Occupied exact tags, case aliases, refs without matching Releases, drafts, existing reservations, and cross-line version identities must block. Four-part builds do not participate in `bump` or replace a stable SemVer baseline.
- Source: obtain remote numeric repository ID, canonical non-fork origin, protected default policy SHA, exact same-repository branch name/SHA/tree and actor role; recheck before effects. Official three-part sources must be current verified remote default or configured production branches; GPID rejects `--allow-non-deployment-branch` and `--reason`. Four-part sources may be any verified current same-repository branch, including `dev`. Choose an explicit line ID whose numeric core bounds contain the version or infer exactly one such line; zero/multiple matches fail, and an explicit ID never bypasses bounds. Stable line selection still requires branch membership; deleted/moved/fork source fails closed.
- Bare-tag route, future canonical GPID command: `<tag>` alone translates to `cg-release start --version <exact unprefixed version> --branch <verified checkout branch>` only after an enabled policy and qualified controller are verified; detached checkout requires explicit source branch, no implicit `--yes`, line, approval, legacy fallback, or extra flags. `plan/start/status/resume` preserve supplied generic arguments. This is a design contract, not an executable instruction now.
