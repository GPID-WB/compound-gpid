# `.cg-docs/` Must Not Be Gitignored

## Problem

`.cg-docs/` contains the primary knowledge output of the Compound Engineering
workflow: brainstorms, plans, and solutions captured via `/cg-compound`. If this
directory is gitignored, the following breakdowns occur:

- Solutions captured on one machine are invisible to all other team members.
- When a new Copilot session starts, `cg-learnings-researcher` cannot find past
  solutions — the entire knowledge-compounding loop is broken.
- Plans and brainstorms are silently lost when a branch is switched or a machine
  is wiped.
- The `/cg-compound` prompt itself becomes pointless: it writes files that git
  immediately ignores.

The bug was silent. No error was raised; the files were written, they just were
never staged or committed.

## Root Cause

In early versions `cg-setup.prompt.md` included `.cg-docs/` in the gitignore
block generated during project setup:

```gitignore
# Compound GPID knowledge base (local thinking artifacts, typically not committed)
.cg-docs/
```

The rationale was that `.cg-docs/` was treated like a personal scratch pad
analogous to `.Rhistory` or `__pycache__`. This was a design mistake — these
artifacts ARE the deliverable of the Compound Engineering workflow and must be
shared across the team via git.

Additionally, old versions of `link.ps1` included `.cg-docs/` in
`$cgGitignoreEntries`, so every `cg-link` run re-added the entry even after a
manual removal from `.gitignore`.

## Solution

**Three-part fix:**

### 1. Remove `.cg-docs/` from `cg-setup.prompt.md` gitignore block

The gitignore block generated by Step A5 of setup now contains only:

```gitignore
# Compound GPID local config (user-specific, never commit)
compound-gpid.local.md
```

No `.cg-docs/` entry. Running `/cg-setup` on a new project no longer gitignores
the knowledge base.

### 2. Remove `.cg-docs/` from `link.ps1` and add orphan-strip logic

`$cgGitignoreEntries` in `scripts/link.ps1` was verified to not include
`.cg-docs/`. The existing block-rewrite strategy (which replaces the entire
CG-managed block on every `cg-link` run) automatically removes any stale
`.cg-docs/` entry left by older versions:

```powershell
# The block-rewrite strips any entry that was in an old block but is no
# longer in $cgGitignoreEntries -- including .cg-docs/ from pre-fix installs.
```

### 3. Add an explicit "does not gitignore .cg-docs/" test

`tests/link.Tests.ps1` now includes:

```powershell
It "does not gitignore .cg-docs/" {
    # ... run gitignore logic with a fresh file ...
    $out | Should Not Match '\.cg-docs/'
}
```

This prevents regression: future changes to `$cgGitignoreEntries` that
accidentally re-add `.cg-docs/` will fail the test immediately.

## Prevention

- **Rule**: Only `compound-gpid.local.md` (per-user config) is gitignored.
  Everything else under `.cg-docs/` is committed institutional knowledge.
- **Test gate**: `link.Tests.ps1` now explicitly asserts `.cg-docs/` absence.
  The test must remain in place.
- **Migration**: Already-linked projects running an old version of `cg-link`
  may still have `.cg-docs/` in their `.gitignore`. Running `cg-link` again
  with the fixed version removes it automatically (block-rewrite strategy).
  Alternatively, users can delete the line manually and run `git add .cg-docs/`.
