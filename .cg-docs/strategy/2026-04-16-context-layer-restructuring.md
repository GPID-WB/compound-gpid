# Strategy Session: Context Layer Restructuring

## Context at Session Start

- Quality Loop milestone fully completed (10/10 features done).
- Performance and Skills Enhancement milestones in progress (1 feature done each).
- User feedback from plugin consumers: copilot-instructions.md is too generic and long; no place for freeform project context; no awareness of multi-folder workspaces.

## Discussion Summary

### Problem 1: copilot-instructions.md is bloated and generic
The file is ~200 lines of framework content identical across all projects — Pester safety rules (irrelevant to consumer projects), R skill routing, coding standards boilerplate. The most premium context window real estate (always injected into every Copilot interaction) is wasted on content that belongs in skills/instructions files.

### Problem 2: No freeform project context
The charter (`compound-gpid.md`) is structured and change-controlled. `compound-gpid.local.md` is just key-value config. There's nowhere to record project-specific facts that don't fit the charter structure (data source locations, work-in-progress notes, domain rules, module descriptions).

### Problem 3: Multi-folder workspace blindness
VS Code workspaces can have multiple root folders. Compound-gpid assumes a single project root and has no mechanism for describing how folders relate to each other or which one is the principal compound-gpid project.

### Decisions reached

1. **Slim copilot-instructions.md**: Stop shipping one-size-fits-all copy. `/cg-setup` and `cg-link` generate a ~40-line project-specific version with: compound-gpid plugin notice, project identity (name, type, languages), essential constraints inline, pointers to charter and context files, workspace folder descriptions.

2. **compound-gpid.context.md**: New freeform file in project root, committed to git. User owns it, edits freely. Topic-based sections (Data Sources, Domain Rules, Work in Progress, Workspace Notes, etc.). No archiving protocol, no frontmatter ceremony. Read by Step 0 in all `/cg-*` prompts alongside the charter.

3. **Charter stays unchanged**: `compound-gpid.md` keeps its current structure and change-control protocol. Growing knowledge goes to context.md, not the charter.

4. **`/cg-compound` enrichment**: After capturing a solution, `/cg-compound` proposes additions to the appropriate topic section of context.md. User must approve. Single ownership model — no separate "user section" vs "AI section." Git history tracks provenance.

5. **Multi-folder workspace**: Workspace section in copilot-instructions.md lists related folders and their role. Prompts updated to respect non-CG folders.

6. **Loading model**: copilot-instructions.md auto-loaded by VS Code (always). Charter + context.md loaded by Step 0 (every `/cg-*` prompt). Ad-hoc chat gets slim instructions inline + pointer to read more if needed.

## Proposed Changes

New milestone "Context Layer" added to roadmap with 4 features:
- `slim-copilot-instructions` — Slim project-specific copilot-instructions.md (generated by cg-link/cg-setup)
- `project-context-file` — compound-gpid.context.md file and Step 0 integration in all prompts
- `cg-compound-context-enrichment` — /cg-compound proposes context.md additions after completed tasks
- `multi-folder-workspace-awareness` — Multi-folder workspace awareness in copilot-instructions.md and prompts

## Decision

Approved. Milestone added to roadmap between Skills Enhancement and Architecture Research.
