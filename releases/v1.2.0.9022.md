# v1.2.0.9022 - Safe-Baseline Rebuild

Prepared release notes. This release has not been published. Windows and Mac
pilots and publication approval are pending. The schema-version-1 payload uses
the preparation date, 2026-10-08, in its required date fields; these fields are
not proof of publication.

## What 9022 Contains

9022 starts from the v1.2.0.9017 baseline and adds the safety fixes in Slices
1-4a. It keeps ordinary commands, adapters, skills, and the research suite.
The fixes preserve user files when old generated files cannot be proved safe
to remove, ignore private local configuration in Git, recover the original
checkout and version pin after a new pinned update fails validation, correct
Windows Python detection and secure long-path staging, and keep a POSIX
installation clone clean. CI has bounded jobs and fresh install, link, and
unlink smoke fixtures.

This is a small rebuild, not a restoration of every 9020/9021 feature. The
following 9020/9021 features are NOT in 9022:

- `cg-help` answers and support evidence.
- Docs browser changes.
- Kilo autopilot and the native plugin.
- The async release controller.
- New release-controller receipts.
- Pages sealing.

Baseline ownership records are still used. The omitted receipts do not mean
that existing project ownership records can be deleted. Existing configuration
access and global Kilo permission behavior are unchanged. Git ignore rules do
not prevent configuration access. Hosted fixtures do not qualify a real Kilo
host or certify a user's installation.

## Supported Migration: Re-Clone

Use re-clone to migrate from 9020 or 9021. Do not use the old updater for the
supported migration. Before publication, approved pilots must use the exact
candidate commit in the external pilot checklist, not a tag or `latest`.
The commands below apply only AFTER publication approval and publication.

### Windows

1. Close terminals and AI tools that use the installation. Record its full
   path, current commit, version pin, and any local changes. Back up affected
   projects, including private configuration and ownership records.
2. Move the entire old installation clone to a backup path outside project
   adapter folders. Keep it; do not delete it or discard local changes.
3. Clone `https://github.com/GPID-WB/compound-gpid.git` at the SAME original
   installation path. In that new clone, run
   `git checkout --detach v1.2.0.9022`. Check that the checkout succeeded. Set
   the new clone's `.cg-version` to `v1.2.0.9022`, not `latest`, before the
   installer: `Set-Content -LiteralPath .cg-version -Value v1.2.0.9022 -Encoding ASCII`.
4. In PowerShell, run `& "<original-install-path>\install.ps1"`. Do not change
   corporate execution policy to force it to run. Stop if it fails.
5. Open a new terminal. Check that `cg-link` resolves to the new clone. In each
   project, run the NEW `cg-link` once, with the adapter selection used by that
   project. Check each result before you continue to another project.

### macOS

1. Close terminals and AI tools that use the installation. Record its full
   path, current commit, version pin, and any local changes. Back up affected
   projects, including private configuration and ownership records.
2. Move the entire old installation clone to a backup path outside project
   adapter folders. Keep it; do not delete it or discard local changes.
3. Clone `https://github.com/GPID-WB/compound-gpid.git` at the SAME original
   installation path. In that new clone, run
   `git checkout --detach v1.2.0.9022`. Check that the checkout succeeded. Set
   the new clone's `.cg-version` to `v1.2.0.9022`, not `latest`, before the
   installer: `printf '%s\n' v1.2.0.9022 > .cg-version`.
4. Run `bash "<original-install-path>/scripts/install.sh"`. Stop if it fails.
5. Open a new terminal. Check that `command -v cg-link` resolves to the new
   clone. In each project, run the NEW `cg-link` once, with the adapter
   selection used by that project. Check each result before you continue.

### If cg-link Blocks Or Preserves Old Plugin Files

Stop on an error or a report that active old plugin files need manual repair.
Do not launch the old plugin between repair steps. Keep old files, ownership
receipts, attestations, journals, locks, and private configuration in place.
Store review copies outside adapter discovery folders. Do not fabricate
ownership, delete journals, recursively remove an adapter folder, or use
`cg-unlink` as a cleanup shortcut.

Have a maintainer review the exact blocked files and records. Only after
separate manual approval, archive the specific blocked managed units together
with their markers and user content, and perform the reviewed repair. Run NEW
`cg-link` again only when the cause is resolved. Automatic cleanup of every old
consumer file is not promised. Record preserved files even when linking
succeeds; do not treat a preserved file as safe to delete.

## Known Limits

- Windows PowerShell 5.1 still has legacy long-path copy and unlink limits.
  A short installation and test-project path reduces this risk but is not a
  guarantee. Stop on path errors; do not delete or rename user project files
  to force success.
- The unpublished recovery updater is not supported. Maintainers must re-clone.
- Clone rollback does not undo all project changes. Keep project backups and
  review any changed files before you restore them.
- 9022 publication is Reserve-only: a non-draft GitHub pre-release with
  `make_latest=false` from the exact pushed source branch. It does not deploy
  documentation and has no Pages or Finalize attestation dependency. Other
  release versions retain their existing completion rules.

## Advanced Note: Old-Updater Acquisition Is Unsupported

This is maintainer guidance, not the migration procedure above. Old pinned
updaters can leave a changed checkout or version pin after a later failure and
can leave stale copies or mirrors in projects.

Before any separately reviewed old-updater procedure, record the original
commit, branch or detached state, and exact pin bytes or absence. Preserve
staged, user, or unknown edits and stop if they exist. Restore ONLY files proved
to be old installer output, from the old HEAD and under manual review. Never
use a blanket reset, checkout of all files, or `--fix` to force acquisition.
Use explicit `cg-update v1.2.0.9022`, never `latest`, and stop on any error.
Acquisition is not completed migration. Reconcile separately with NEW 9022
`cg-link` and process-only `CG_SKIP_UPDATE=1`; unresolved active plugin files or
incompatible journals still require reviewed manual repair.

## Rollback

The old clone remains available if 9022 does not work. Stop using the new clone,
close affected terminals and tools, move the new clone aside, and move the old
clone back to its exact original path. Run the old clone's installer and open a
new terminal. Check the old commit, wrapper paths, and version pin. Restore
project files only from reviewed backups. Keep both clones and failure logs
until the result is understood. Do not assume that restoring a clone restores
every project side effect.
