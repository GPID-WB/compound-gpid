# v1.3.0 - Stable rebuilt line

## First Stable Release

v1.3.0 is the first stable release of the rebuilt line. It brings together the
safer upgrades from 9024, the default-settings fixes from 9025, and the new quick
upgrade guide. Technical and research commands, adapters, and skills remain
available. Installing, updating, and linking do not require Kilo.

## Upgrade

Follow the [Windows and macOS upgrade guide](https://gpid-wb.github.io/compound-gpid/#page=upgrade)
for older installations, fresh installs, project refresh, and removal.

On **v1.2.0.9024 or newer**, run this from your **home folder**, not a project:

```text
cg-update v1.3.0
```

Open a new terminal. In each project, run the NEW `cg-link --check`, then
`cg-link` once, keeping its adapter selection. Review any reported manual
action. Use the explicit version: `cg-update latest` follows `main`, not the
GitHub Latest release.

On **older versions**, follow the guide's one-time migration using a fresh
v1.3.0 clone. Keep the old installation backup and the printed rollback
command. Do not run the old updater or linker first.

## Safer Project Refresh

- Migration keeps the old installation in a sibling backup, installs at the
  original path, and pins the chosen version.
- `cg-link --check` is read-only. Edited, unowned, and user-added files are
  preserved for review rather than silently replaced.
- The one-time legacy Copilot instructions transition saves original bytes in
  `.github/copilot-instructions.md.pre-9024.bak`. Review and merge your custom
  instructions from that backup.
- PATH warnings explain how to use the new installation instead of an old
  command that takes precedence.
- Older `compound-gpid.local.md` files containing notes but no settings block
  use defaults; an initial UTF-8 BOM is accepted. Your file is not rewritten.
  Run `/cg-setup` later if you need settings.
- Repeated linking removes duplicate managed `.gitignore` entries and obsolete
  internal copies.

## Tested Coverage

Windows and macOS CI fixtures cover migration from `v1.1.11` and
`v1.2.0.9021`, updates through the installed 9024 updater, older-updater
recovery, and the published quick-guide commands. They check backups, preserved
user files, default settings, pins, read-only checks, and repeat linking.
Required gates also run native Python and Pester tests on both platforms.

These are isolated fixtures, not proof for every historical installation or
a real Kilo host. Release-preparation check results are recorded in the PR;
publication still requires full CI on the final main commit.

## Known Limits

- Migration supports standalone Git clones, not worktrees or linked installation
  paths. Existing backups or multiple installations can require explicit
  selection or recovery. Local installation edits stay in the backup, not merged.
- Rollback restores the installation, not project changes or every PATH/profile
  write. Keep reviewed project backups.
- Windows PowerShell 5.1 long-path copy/unlink limits remain. Use short
  installation paths; do not remove user files to force success.
- Keep blocked or preserved files and resolve the reported manual action.
  Do not delete adapter folders or use unlink to bypass conflicts.

## Publication

This is a prepared stable-release payload. Its dates record preparation, not
publication. Stable publication requires promotion to `main`, full CI, Reserve,
verified documentation deployment, Finalize, and a reviewed attestation-evidence
PR. Making v1.3.0 GitHub Latest is a separate owner action.
