# v1.2.0.9025 - Default Settings

## Default Settings

When `compound-gpid.local.md` has no top YAML frontmatter block, configuration
reads use the default `cg` suite and config schema version `2` in memory only.
Empty files, whitespace, and Markdown notes do not need a settings block. The
reader does not rewrite the file to insert defaults.

An initial UTF-8 BOM is ignored when reading configuration. A top frontmatter
block, when present, still receives strict validation. Malformed or unterminated
blocks, duplicate or unknown keys, invalid values, and unsupported schema versions
remain errors with filename and line diagnostics.

`cg-link --check` remains read-only: no configuration, project, or global writes.
Using defaults does not turn a check into migration or repair.

## Upgrade To 9025

From `v1.2.0.9024` on Windows or macOS, run this outside linked project directories
(for example, from your home directory):

```text
cg-update v1.2.0.9025
```

Then run the NEW `cg-link` once per project, keeping its adapter selection. Use
the explicit version, not `latest`.

From older versions, follow the [Windows and macOS Upgrade Guide](https://github.com/GPID-WB/compound-gpid/blob/v1.2.0.9024/docs/upgrade.md)
to migrate and install `v1.2.0.9024` first. Then run `cg-update v1.2.0.9025`
and the NEW `cg-link` once per project.

Keep installation and project backups. If linking reports blocked or preserved
files, keep them and review the reported manual action. Do not delete adapter
folders or use unlink to bypass conflicts.

## Tests Added

Tests added cover default-settings configuration reads, initial UTF-8 BOM
handling, strict validation errors, read-only checking, and Windows/macOS
upgrade/update fixtures. These are coverage additions, not a claim that local
or hosted gates have passed. They do not qualify every historical installation
or a real Kilo host.

The installed 9024 updater is tested from a neutral directory, followed by the
NEW linker in the original valid-config project and a second legacy-config
project. Running that old updater inside a linked project can stop at its stale
manifest guard; use the neutral-directory update path instead.

## Publication

Every four-part `vX.Y.Z.N` tag is Reserve-only: a non-draft GitHub pre-release
with `make_latest=false`. No Finalize, documentation deployment, or attestation
applies. Required payload dates are preparation timestamps, not publication
proof. Publication requires green local, push, and FULL CI gates.
