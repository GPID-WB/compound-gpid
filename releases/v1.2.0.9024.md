# v1.2.0.9024 - Safer Upgrades

## Upgrade From Any Older Version

Pinned and `latest` users use the same path: clone the official repository at
`v1.2.0.9024` into a separate fresh folder, then run the NEW clone's migration
script by full path. Do not run the old updater or linker first.
Migration keeps the old installation in a sibling backup, installs at the
original path, and pins `v1.2.0.9024`. It does not reconcile projects.

Follow the [Windows and macOS Upgrade Guide](https://github.com/GPID-WB/compound-gpid/blob/v1.2.0.9024/docs/upgrade.md)
for default/custom paths, multiple installations, checks, PATH repair, and rollback.
After migration, open a new terminal and verify `cg-link` resolves to the new
installation. A PATH warning keeps the verified installation and prints repair
guidance; do not run a shadowing old command.

Stay pinned. Do not run `cg-update latest` until announced: today `latest`
tracks `main`, which still contains the old line, not the newest four-part tag.

## Project Files And Notices

Run the NEW `cg-link --check`, then `cg-link` in each project, keeping its adapter
selection. The check is read-only: no update, Kilo launch, or project/global
writes. Review blocks or preserved conflicts before linking.

Edited or unproven files are kept and reported as `manual action required`;
user-added files are kept. Do not delete adapter folders or use unlink to bypass
conflicts. The one-time legacy managed Copilot instructions transition first
saves exact prior bytes to `.github/copilot-instructions.md.pre-9024.bak`, then
replaces the instructions. Review and merge custom instructions from that backup.
Later replacement needs unchanged ownership proof. Existing conflicting backups
are preserved and need manual action.

The original reveal.js and Marked vendor license notices are restored at
`presentation/vendor/reveal.js/LICENSE` and `LICENSE.marked.txt`.

## Known Limits And Rollback

Only standalone Git clones are supported; worktrees and linked installation
paths are refused. Multiple installations need explicit path selection. Existing
backups stop a new migration until inspected and recovered through rollback.
Local installation edits remain in the backup, not merged into the new clone.
Windows PowerShell 5.1 long-path copy/unlink limits remain; use short install paths.

Use the migration script's explicit rollback mode and the exact command it
prints. Rollback restores the old installation and keeps the current one aside.
It does not undo project changes. Installer PATH/profile writes are not
snapshotted; review those manually and restore only reviewed project backups.

## Publication

Every four-part `vX.Y.Z.N` tag is Reserve-only: a non-draft GitHub pre-release
with `make_latest=false`. No Finalize, documentation deployment, or attestation
applies. Required payload dates are preparation timestamps, not publication
proof. Publication requires green local, push, and FULL CI gates.
