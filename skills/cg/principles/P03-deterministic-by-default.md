# P3 Deterministic by default

Anything code can produce or check is produced or checked by code, and running it again gives the same result. The model judges; it does not compute, copy or transcribe.

**Why.** A result nobody can regenerate cannot be reviewed, defended or corrected. A script is something a reviewer can rerun. A model's output is not.

## In production

- **Plan.** Mark each step "by code" or "by judgement". For every step by code, name the lever: the script, pipeline target, test or generator that will do it.
- **Work.** Do the first unit by hand, then build the tool and prove it by rerunning it on that unit. Build the smallest script that does the job.
- **Outputs.** Every table, figure, number in text, rendered page and index comes from one command that starts from the inputs. Nothing is typed, pasted or edited by hand afterwards.
- **Randomness.** Set a seed and record it wherever the code samples, bootstraps, simulates or splits.
- **Environment.** Pin it: `renv.lock`, `uv.lock` or `poetry.lock`, the Stata version and ado versions.
- **Paths and time.** Use project-relative paths. Keep timestamps out of outputs that are compared.
- **Reruns.** Make each operation safe to run twice: derive the step from the state that exists, write to a temporary path, then rename.

## Evidence it leaves

- The script, pipeline or check, in the diff. No script in the diff means the principle was not applied.
- The one command that regenerates the outputs, recorded in the project's verification profile.
- A lockfile, and the seed where one is used.
- The repro record: two runs, same digests.

## Verifier: `determinism`

**At plan stage, inspect** the plan for steps that rely on the model or on manual effort where a script could do the job.

**At review stage, inspect** the diff, the outputs and the work report.

Flag when:

- a table, figure or reported number is not regenerated by a script from the inputs;
- a number appears in prose that no output file contains;
- a step needs a person to click, copy, paste or rename;
- code samples or simulates with no seed;
- the environment is not pinned;
- a path is specific to one user or machine;
- results depend on row order, parallel scheduling or the clock;
- a run fetches from the network with no saved snapshot;
- an agent instruction asks the model for clerical work a command could do.

**Prove a flag** by naming the output and showing that no script writes it, or by running the pipeline twice and showing the outputs differ. For each flag, propose the code that would replace the manual or model step.

**Leave alone:** interpretation, choice of method, and one or two obvious edits. Those are judgement or trivial, and neither needs a tool.

## Deterministic checks

- `cg.py repro`: run the declared command twice and compare output digests.
- A lockfile exists for each language the project uses.
- A search of changed files for sampling and random calls with no seed nearby.
- A search of changed files for user-specific absolute paths.
