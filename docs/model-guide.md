# Model Guide - Compound GPID

## Default Behavior

Ordinary workflow prompts (`/cg-brainstorm`, `/cg-ideate`, `/cg-plan`,
`/cg-plan-review`, `/cg-review-repos`, `/cg-strategy`) do NOT hard-code a
model. They inherit whichever model the user has selected in the GitHub
Copilot model picker.

When Copilot Auto is selected, Compound GPID prompts must not infer or name the
hidden underlying model. If generator vendor matters for review routing, record
`generator-model: unknown`, `generator-vendor: unknown`, and
`generator-source: model-picker` unless the user supplies the actual model.

## Recommended Model Selection

| Use case | Recommended model |
|----------|-------------------|
| Normal daily use | OpenAI model selected in the picker, or Auto when the user wants Copilot to choose |
| Implementation, bug fixing, diagnostics fixing, PR verification | GPT-5.3-Codex |
| Routine review and architecture/data reasoning | GPT-5.4 or GPT-5.5 |
| Extremely simple mechanical status/update work | Claude Haiku 4.5 when a cheap explicit model is justified |
| Cross-vendor review contrast | Use a different vendor from the generator, with OpenAI preferred when code was generated by Anthropic |
| High-stakes escalation | User-selected premium model only, with explicit rationale |

## Governance Principle

- Explicit model assignments are OpenAI-first.
- GPT-5.3-Codex is the preferred coding model when Copilot accepts that exact
  model string in prompt/agent frontmatter.
- Inherited model-picker prompts are valid exceptions to OpenAI-first policy
  because the user controls the model at runtime.
- Sonnet is a targeted fallback or cross-vendor contrast model, not a blanket
  default for coding or review workflows.
- Haiku is allowed only for extremely simple mechanical workflows.
- Premium usage is user-initiated or reserved for dedicated deep-review
  workflows. It is never silently imposed by prompt metadata.

The source of truth is `.github/shared/model-catalog.json`. `docs/model-guide.md`
must stay in sync with prompt/agent frontmatter and the catalog assignment
matrix.

## Validation Guardrails

Before merging model or prompt-governance changes in the `compound-gpid` repo,
run the context audit:

```bash
python3 scripts/cg_audit_context.py --root . --output-dir .cg-docs/cost --format both
```

The generated guardrails must show:

- no unknown model names;
- no prompt or agent without exactly one catalog role;
- no ordinary model-picker prompt with `model:` frontmatter;
- no Haiku assignment outside mechanical workflows;
- no Sonnet default without fallback or cross-vendor rationale;
- no model-guide drift;
- no unconfirmed runtime claim about Copilot model-picker behavior.

For release candidates, also complete
`.cg-docs/cost/token-optimization-release-checklist.md`. The static audit can
verify prompt metadata and guardrail text, but VS Code/Copilot must still
validate runtime model-picker behavior, exact GPT frontmatter support, and
routed agent dispatch. See the
[Token Optimization Validation](workflow.md#token-optimization-validation)
procedure in `workflow.md` for the full step-by-step process.
