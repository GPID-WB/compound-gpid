# renv Reference

`renv` provides project-local R library isolation so every collaborator uses exactly the same package versions. The lockfile (`renv.lock`) is the source of truth.

## Lifecycle Commands

| Command | When to run |
|---------|-------------|
| `renv::init()` | Once, when creating a new project |
| `renv::snapshot()` | After `install.packages()` / `pak::pak()` or removing a package |
| `renv::restore()` | After `git pull` when `renv.lock` has changed |
| `renv::status()` | Audit: are installed packages consistent with the lockfile? |
| `renv::update()` | Intentionally upgrade packages (follow with `snapshot()`) |

```r
# New project bootstrap
renv::init()

# After adding a package
pak::pak("collapse")
renv::snapshot()

# After cloning or pulling
renv::restore()

# Health check
renv::status()  # Should report: "No issues found"
```

## Project-Local vs Global Library

- `renv` creates a **project-local library** under `renv/library/`.
- This directory is **gitignored** — never commit it.
- `renv.lock` records exact package versions and sources — **always commit this**.
- Packages are cached globally in `~/.cache/R/renv/` so multiple projects sharing a package version don't duplicate downloads.

## Lockfile Conventions

- Commit `renv.lock` with every package change using message `chore(renv): update lockfile`.
- Never manually edit `renv.lock` — always use `renv::snapshot()`.
- Keep `renv/activate.R` committed (auto-generated by `renv::init()`).

## .gitignore Pattern

```gitignore
# renv
renv/library/
renv/local/
renv/staging/
renv/python/
.Rprofile          # only if auto-generated by renv — keep if manually configured
```

Always keep `renv/activate.R` and `renv.lock` tracked.

## Common Issues

| Problem | Fix |
|---------|-----|
| `renv::restore()` fails on a package | `pak::pak("pkg")` then `renv::snapshot()` |
| Library out of sync after branch switch | `renv::restore()` |
| New package not in lockfile | `renv::snapshot()` |
| `renv::status()` reports phantom packages | `renv::snapshot(type = "explicit")` uses `DESCRIPTION` to scope |
